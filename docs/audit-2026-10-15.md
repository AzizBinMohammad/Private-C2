# Repository Audit — 2026-10-15

Full audit of Private-C2: documentation vs. implementation, phase-plan
verification, CLI↔UI integration mapping, source review, and the fixes applied.

Method: every claim below was checked against source (`file:line`) and, where
marked **reproduced**, against a running server with a real implant. Nothing here
is inferred from documentation alone.

Baseline before any change: `go test ./pkg/... ./server/... ./client/...` passed;
`go vet` clean; 59 files failed `gofmt`.

---

## A. Project understanding

Private-C2 is a Go 1.23 C2 framework for authorized red-team engagements: a TLS
implant listener, an operator REST API + embedded web portal, a multi-transport
implant, engagement scoping with fail-closed kill switches, hash-chained audit
logging, and a read-only OT/ICS assessment module with 17 industrial protocol
clients.

Nine Go modules linked by `go.work`. Three entry points are live:
`cmd/server` (listener + REST API + metrics), `cmd/client` (operator REPL),
`cmd/implant` (beacon loop). `cmd/mcp` is a working MCP server over the REST API.
`cmd/builder` prints usage and exits.

The single most important structural fact: **the live binaries bypass almost
every structured package.** `cmd/implant` uses only `implant/modules/screenshot`
and `pkg/protocol`; `cmd/client` uses only the standard library plus the new
`client/api`; `cmd/server` uses `server/{c2,api/httpapi,store,telemetry}` and
`pkg/tlsutil`. Everything else under `implant/`, `client/{cli,console,transport}`,
`server/{build,core,api/grpc,api/middleware,config,c2/listener}` compiles but is
never executed.

## B. Documentation and phase assessment

All eight phase documents are stamped `## Status: DONE`. Verified status:

| 3 Transport layer | DONE | PARTIAL | HTTPS uses base64 only, not the envelope; DNS responses carry no C2 data and chunk reassembly is dead code; WireGuard is a stub; **no listener is ever constructed** |
| 4 Implant modules | DONE | PARTIAL | `execute-assembly` and interactive PTY missing; every module except `screenshot` is unimported |
| 5 Build pipeline | DONE | PARTIAL | Output formats are magic-byte prefixes, obfuscation is inert, gRPC build RPCs absent, `stages/stager.go:88` passes a nil context to `Compile` (latent panic) |
| 6 Client console & CLI | DONE | **CLAIM CONTRADICTED** | Every command handler prints "Stub: Would call gRPC …"; the package has no importer; declared deps (cobra/grumble/tablewriter) are in no `go.mod` |
| 7 Integration & hardening | DONE | PARTIAL | All 24 integration tests are `t.Skip`; `make proto` is a placeholder; "TLS 1.3 only" and "no hardcoded credentials" checklists are both false; the Docker stack cannot start (see F) |
| 8 OT interface | DONE | PARTIAL | 10–11 of 17 protocol clients are real; `isSafetyCritical` always returns `false`; the "MUST pass" safety-interlock tests do not exist; the hidden-interface gate is absent on the live HTTP path |

Documentation inconsistencies found:

- `docs/decisions.md:170-172` states the project "does not appear to be a fork"
  with "no recognizable framework structure from Sliver", while
  `docs/origin.md` documents close structural derivation from Sliver
  (identical directory names, parallel event/session/file layout). These two
  documents contradict each other and should be reconciled.
- `docs/decisions.md`, `docs/architecture.md` and the phase docs describe the
  `handler.go` monolith, `strings.Contains` scope check, and two incompatible
  audit hash algorithms as current. All three were fixed by the earlier
  refactor and the docs are now stale (partially corrected on 2026-10-15).
- `README.md` claims "RBAC ... with mTLS client certificate auth". Neither is
  true of the running server: mTLS is explicitly disabled and there is no
  authorization layer on the REST API.
- `docs/architecture.md` and `CLAUDE.md` correctly describe most unwired
  packages, but neither documents the client-side equivalent gap (`cmd/client`
  beside `client/`) or the unwired `server/c2/listener` layer.

## E. Implementation roadmap

Ordered by dependency and risk.

**Completed 2026-10-15** (all verified; see F):

1. Authenticated shared operator client (`client/api`) + CLI login — resolves 1.
2. CLI task-poll contract aligned with the portal — resolves 5.
3. CLI `upload` payload format — resolves 12.
4. `make cross-compile` and `quickstart.sh` implant path — resolves 10.
5. Portal `esc()`/`jsArg()` escaping and all 9 inline-handler sites — resolves 9.
6. Portal response-key alignment + `hostname` in the status response — resolves 14.
7. Portal payload download via authenticated fetch — resolves part of 15.
8. `make test`/`make lint` cover all 9 modules.

**Second batch, completed 2026-10-15** (mTLS, on the user's instruction to
enforce it and update the quickstart) — resolves finding 2:

- `ServerTLSConfig` sets `RequireAndVerifyClientCert` when a CA is supplied.
- `ClientTLSConfig` takes `ClientOptions{CAPath, CertFile, KeyFile, Insecure}`
  and errors when no CA is given, replacing the silent `InsecureSkipVerify`
  fallback (previously known-issues #5). Verification can only be disabled by
  the explicit `--insecure` flag.
- `scripts/setup-ca.sh` issues an implant client certificate (`clientAuth` EKU).
- `scripts/quickstart.sh` passes `--ca/--cert/--key` to the server and
  documents the same flags for implant deployment.
- Three handshake tests prove a valid client cert connects, a missing one is
  rejected, and one from a foreign CA is rejected.
- Verified end to end: rejection is `tls: certificate required`; an implant with
  a CA-signed cert registers and runs `shell`/`pwd` tasks through the CLI.
- Deleted `cmd/server/tls_test.go` and `cmd/implant/tls_test.go` as duplicated
  copies of the (now superseding) `pkg/tlsutil/config_test.go`.

**Third batch, completed 2026-10-15** — resolves findings 6, 7 and 8:

- `ImplantServer` gains `CloseSession`, `LockSession`, `UnlockSession` and
  `snapshot()`. `DELETE /api/sessions/{id}` closes the live connection, reaps
  the session's task queue and results, and returns 404 when the session is not
  live. Locks are held in memory; a second operator gets 409 rather than
  silently taking a held lock.
- `ListSessions`/`GetSession` return copies, eliminating the data race where the
  HTTP layer marshalled a session while the connection loop wrote
  `LastCheckin`.
- New `server/c2/listeners.go`: a real listener registry. `POST /api/listeners`
  binds a TLS socket and only records `running` after the bind succeeds;
  `DELETE` closes it; `GET` reports status and `active_connections` from the
  running process. Unimplemented transports are refused with 400 instead of
  stored as `running`. `cmd/server` now registers its startup listener through
  the same path.
- Verified live: a listener created through the API accepted an implant that
  registered successfully; deleting it freed the port; a repeat DELETE returned
  404; an unsupported type returned 400 with no database row written.
- The portal offers only implemented listener types, hides Stop for stopped
  listeners, shows `Locked By`, and no longer claims session kill is
  irreversible.

**Next, in order:**

1. **Add the OT execution path** (finding 3): define OT task types, have
    `cmd/implant` dispatch them into `implant/modules/ot`, and add an endpoint
    that starts an assessment. Without this the framework's headline feature
    cannot run.
2. **Authorization layer** (finding 4): apply role checks to operator
    management and payload generation; delete or correctly wire the fail-open
    `middleware/rbac.go`.
3. **Memory hygiene (remaining)** (finding 7): results for still-live sessions
    are never pruned, and expired auth tokens are never removed from
    `AuthManager.tokens` (there is no logout/revoke path). Queue/result reaping on
    session removal and the `LastCheckin` race are already fixed.
4. **`/api/audit/export`** (finding 15) backed by `pkg/audit/export.go`.
5. **Fix the Docker deployment** (finding 11): wire `server/config`, correct
    the exposed ports, set a writable `WORKDIR`, and either ship the Go toolchain
    plus source in the runtime image or drop server-side payload generation from
    the container.
6. **`gofmt -w`** across the repo as a standalone commit (finding 20).
7. Consolidate `cmd/mcp` onto `client/api` to remove the duplicated client.
8. Phase 6 decision: either wire `client/cli/commands` to the REST API and
    delete `cmd/client`'s inline REPL, or delete the dead tree. Two competing
    CLI architectures currently coexist.

**Deliberately not scheduled:** the gRPC path (`proto/v1`, `server/api/grpc`,
`server/core`, `server/api/middleware`) and `server/build`. `docs/decisions.md`
states REST is the operator transport; reviving gRPC is an architectural change,
not a defect fix, and needs an explicit decision first.

## G. Remaining risk

The critical path — implant registration, tasking, result collection — works and
is now reachable from both the CLI and the portal. The largest remaining risks
are that the OT/ICS capability cannot execute at all despite being the project's
headline feature, that session and listener control report success without
acting, and that the REST API has no authorization layer and no enforced mTLS.
